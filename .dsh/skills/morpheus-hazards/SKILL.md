# Morpheus known hazards

Mirrors `KNOWN-HAZARDS.md` in the repo root — that file is authoritative and is
appended to by `revertSelfDevPush` and the deploy-failure auto-diagnose flow.
Read it in full when a change touches any area below.

## The list

| # | Hazard | Rule |
|---|---|---|
| **H1** | `server/src/lib/github.js` is imported by every compile + deploy path. A self-dev change once shrank it to suit one caller and broke every other importer at import time — all compiles died before reaching GitHub Actions. | **Never remove or rename an export, or change an exported function's return shape, without updating every caller in the same change.** Adding is fine. When in doubt expose both shapes. Verify runs a cross-file check for named imports of local files that aren't exported. |
| **H2** | `entities.js` `scope()` already lets admins see all rows. An admin query that *also* filtered by `created_by_id: user.id` returned nothing. Still live at `server/src/functions/generateSelfDevManual.js:87`. | In admin-only / self-dev handlers, **do not add `created_by_id: user.id`** to a Prisma `where` for data the admin should see system-wide. Scope by `project_id` / `project_type`. |
| **H3** | `npm run build` runs `scripts/sync-capabilities.mjs` as `prebuild`, which **rewrites `src/MORPHEUS_DESIGN_PLAN.md`**. | Never include that file in a change unless the change is specifically about it — it's build noise. `git checkout -- src/MORPHEUS_DESIGN_PLAN.md`. |
| **H4** | `npm install` in `server/` rewrites `server/package-lock.json` (drops unresolvable `@base44/*` entries). It is gitignored. | **Never add `server/package-lock.json` to a change.** |
| **H5** | `applyEdits()` (`server/src/lib/projectUtils.js`): a `find` matching 0 or 2+ times leaves the file **untouched** — a no-op, never a partial edit. A "successful" diff-mode change can silently ship nothing. | Use `edits` only when `find` is a **verbatim, unique** span of the current file — never reconstructed from memory. Otherwise send full `content`. |
| **H6** | `invokeAI` throws `OUTPUT_TRUNCATED` on `finish_reason: length`. Omitting `maxTokens` hands control to an undocumented provider default that has truncated real builds repeatedly. | **Any `invokeAI` call that can produce multi-file or long output must set a generous explicit `maxTokens`.** |
| **H7** | Self-dev pushes must never touch `base44/`, lockfiles, or binaries. A 2026-09-06 rewrite computed deletions over the whole remote tree and would have wiped them from `main` on the first push. | Deletions are only ever computed over paths where `shouldExclude()` is false; **a truncated remote tree means no deletions at all that push.** |
| **H8** | The backend deploy only runs `prisma generate`, never a migration. Migrations are hand-run `server/prisma/*.sql`. | Every `schema.prisma` change ships `server/prisma/selfdev-<slug>.sql` in the **same change** — idempotent, additive-only DDL. `pushSelfDevToGithub` blocks a schema change with no migration. |
| **H9** | **Production data-loss incident.** `pushSelfDevToGithub.js` diffs against self-dev's local `ProjectFile` snapshot, not live `main`. While it sat stale, a separate Claude Code session merged ~a dozen PRs to `main`; the next push force-corrected `main` back toward the stale snapshot, deleting `blockWidget` (a shipped security fix) and ~45 files. | **Treat self-dev and every other writer of `main` as sessions that must not overlap without a resync.** Click SYNC FROM GITHUB immediately before any BUILD → PUSH turn. The longer-term fix is now **built** (`lib/selfDevDrift.js`): it refuses a push whose `Project.synced_commit` disagrees with main's live HEAD, or that would delete more than 10 files unscoped — on the PR path *and* the direct-to-main path. Overriding it needs `acknowledgeDrift`, which `force` deliberately does not imply. It needs `server/prisma/selfdev-add-synced-commit.sql` to have been run for the precise check; **until then any deletion is refused outright**, because with no sync point a 1-2 file stale drift is indistinguishable from a deliberate removal. |
| **H10** | Self-dev built a page against `xtools.wmcloud.org/api/user/global_stats/{username}` — a route that **does not exist** (404) — plus an invented wiki username, and swallowed both failures in try/catch so the page hung on "Loading..." forever. | **Never write code against an external API's shape from memory when a cheap real check exists.** Verify with one HTTP request first. The planner must flag *every* endpoint it isn't certain of; `lib/externalApiCheck.js` now calls flagged endpoints before the coder writes against them. |
| **H11** | `entities.js` reads with **no `select`**, so Prisma fetches every column. On a DB where a new column hasn't been hand-applied, that read throws `P2022 — column does not exist`. Because `CommandDeckContext.jsx` lists every `Deck*` entity on **every Deck load**, one unapplied column takes down the *whole Deck*, not just the new feature. H8 says ship the migration with the change; H11 is the sharper fact that **you cannot assume it has been applied when the code deploys.** Near-miss 2026-09-19: a `deck_insight_enabled` column on `DeckBusinessProfile`. | **Prefer not adding the column.** Reuse an existing control/column when the meaning genuinely matches (the proactive-insight opt-out became the existing `DeckWidgetInstance.enabled` flag for `jarvis_suggestions` — zero migration). If a column is truly required, every read of that model gets an explicit `select` **and** the defensive read/write pair (`lib/templateCompat.js` + `Settings.jsx`'s retry-without-the-field) in the same change. A missing column must degrade to the old behaviour, never to "feature off for everyone". |
| **H12** | **46 minutes of production API downtime (2026-09-19).** `lib/deckInsightSchedule.js` was mirrored from `freshnessSchedule.js` and kept its `./queue.js` import, but it lives in `src/lib/`, and there is no `src/lib/queue.js` — the real file is `server/src/queue.js`. `index.js` imports it at boot → the container died at module load → every request got `503 no healthy upstream`. `node --check` validates syntax and never resolves a specifier; lint doesn't either; the integration tests imported `deckInsight.js` directly and so never loaded `deckInsightSchedule.js`; and the one local boot attempt used `timeout`, absent on macOS, so it failed before `node` ran and looked like a pass. | **A new module is not verified until something has actually loaded it.** `scripts/verify-server-imports.mjs` resolves every relative specifier in `server/src` + `server/scripts` with exact case, in the guards job. After registering anything in `index.js`/`worker.js`, **boot it**: `NODE_ENV=production node src/index.js` then hit `/api/health`. Testing a module is not testing everything that imports it — and never trust a command that failed to run. |
| **H13** | An external query can succeed, return nothing, and stay that way forever (2026-09-17, `6dc8c1e`): the Gmail inquiry sync filtered on `category:primary` with no date bound, so it logged success on every run and dropped every real inquiry that ever arrived. Not a classifier miss — the messages were never fetched, and nothing said so. | **A query whose emptiness is indistinguishable from a real empty result must be bounded and sampled**: assert a non-empty result against one known-good item, and never let "the fetch returned nothing" log as success. H10 is a 404; this is a silent zero. |
| **H14** | A green build can ship an artifact that cannot run (2026-09-20, `2bc0a05` and neighbours): build/install steps that report success while failing — `pip3 install … \|\| true` aborting on PEP 668, and similar. | **Never neutralise a build or install step with `\|\| true`,** and do not treat the build log as proof: the artifact must be run (or its entry point loaded) before the change is called verified. |
| **H15** | A shared module can lose its *behaviour* and pass every gate (2026-09-13/14, `1891ae6` + `4e8ed1e` reverted, `969232a`): `server/src/ai.js` went from 585 lines to 153 in a self-dev push, dropping `fetchWithTimeout`, model auto-discovery, the temperature override, credit reserve/reconcile and truncation handling — with syntax, lint and build all green. | **When a shared module changes, diff what it *does*, not only what it exports** (H1 covers a dropped export; this is the shape-unchanged case). A deleted `// WHY` comment is the signal that a behaviour left with it. No guard sees this yet — review it by eye. |
| **H16** | An admin-scoped read can expose another account's private data (2026-09-17, `71c6bbd`): `scope()` lets admins see all rows, so Rob's `/deck` silently merged another account's Deck tasks and preferences into his view. Private data crossed accounts and nothing failed. | **For any personal-data model (`Deck*` especially), an admin-scoped read must be a deliberate, explicit widening** — never the default `scope()` happens to produce. Assert `scope()` cannot return another account's rows, and treat "the admin can see everything" as a disclosure decision, not a convenience. |
| **H17** | A check that never ran reads as a check that passed (2026-09-20, PRs #258/#259): GitHub does not create a `pull_request` workflow run when it cannot compute the merge commit and never backfills it, so both PRs had only green Netlify previews and **no CI run at all**. `getPullRequestChecks()` asks "did anything fail?" → `passing`, and the "no checks yet" grace did not apply because checks existed. A green preview was one step from being the only gate before production. | **"Nothing failed" is not "the gates ran".** A repo whose CI we know must require its gates **by name, present and successful** (`skipped`/`neutral` are not passes), the list living in `server/src/lib/engine/requiredChecks.js` and asserted against the workflow's own job names by `scripts/verify-merge-gates.mjs`. A repo with no known gates keeps the old behaviour; a conflict is answered as a conflict, because that is why the run never appeared. |
| **H18** | A `let`/`const` declared inside a `try` block is invisible to its sibling `catch`, and to everything after the block. Three refactors moved `chatWithMorpheus`'s build state (`appliedOps`, `reply`, `fullReply`, `truncatedFiles`, the rework counters) inside the turn's `try`, so the reads after it threw `ReferenceError`: #356 killed every code build, #361 fixed one of the 17 reads, #362 found the other 16 — including the recovery path #358 added, which had therefore never run. Syntax check, import resolver and boot smoke all stay green; none of them call the function. | **A declaration that must outlive its block goes outside it.** Before reading a name in a `catch`/`finally`/after a `try`, check it is not declared inside that block. `no-undef` decides this exactly, and is now on for `server/src/**` in `eslint.config.js`. |

## Reviewer instruction

For any proposed change, walk this table and state explicitly whether each item
| **H19** | A guard can be satisfied by the bug it exists to prevent. Six times in one session: `verify-usage-observability.mjs` **required** `model: resolvedModel` in a catch where it is in a temporal dead zone, so the guard demanded H18's reference error (every provider error in the product reported it instead of the real one); a check asserted words that survived in a now-unused string after the line injecting them was deleted; another matched a literal call shape that broke on refactor while the behaviour was unchanged; a `/usage` check read the whole file and was satisfied by `/refund`; three matched their own comments; and `dependencyProblems` reported **no problems** for a manifest declaring an unbuildable package because the guard passed the wrong shape. 83 guards in this repo, 40+ sabotageable, none proving it can fail. | **Break the subject and confirm the check goes red before believing it.** One honest mutation — remove the guard clause, invert the condition, rename the field — and expect a non-zero exit. Strip comments before matching source (`const code = (src) => …`) and assert behaviour (call the function) rather than a spelling (grep the file). A guard that examines nothing is not a pass — see `scripts/verify-verifier-coverage.mjs`, the existing guard-that-tests-guards. |
| **H20** | A build can only run on the machine that made it, and nothing says which machine that was. `mac-app`'s Python path ran on `macos-latest` only, so every Python/Qt disk image was arm64-only and an Intel Mac refused it with "not supported on this Mac" — no Intel build to ask for, and the only explanation inside the app that would not open. Separately, GitHub's Action artifact zip flattens the ~400 symlinks a PyInstaller `.app` is built from, so a *correct* macOS build downloaded from CI dies with `SIGSEGV` in `QtCore.abi3.so`'s static initialiser before Python starts (PyInstaller #9367). | **Name the machines the output runs on, and offer one download per machine.** A single-string `runner` means "whatever architecture CI has today"; a target that cannot cross-build declares one runner per architecture and the release carries `app-macos-intel.dmg` beside `app-macos-apple-silicon.dmg` — the filename is the only fact a person browsing a release can read. Reporting the architecture in a CI log is not an option; the download IS the option. Ship macOS bundles as a `.dmg` (hdiutil keeps symlinks) and never as a raw Action artifact — test with `find TheApp.app -type l | wc -l`. `scripts/verify-mac-app-arch.mjs`. |
| **H21** | A save that fails reads as a build that failed. 2026-10-02: a macOS build published a 103 MB and a 113 MB disk image; the save downloaded both from GitHub and re-uploaded ~217 MB **sequentially inside one HTTP request**, so Cloudflare's ~100 s proxy read timeout cut it before the browser's own 210 s (`API_FETCH_TIMEOUT_MS`) could fire. The client saw `NetworkError`, `useWorkspace` returned `{ error }`, and the panel put a SUCCESSFUL build into BUILD FAILED with "tap RECOMPILE" — to rebuild an app that already existed and was still downloadable. | **The build's verdict is the build's; nothing downstream may overwrite it.** Put any job longer than the proxy timeout off the request path and poll it, persist progress as it goes so a reload can reconstruct it, and report a save failure as its own state that names the working fallback — never as the phase that offers a rebuild. The other half of H14: a green build must not be reported as red either. `scripts/verify-artifact-save-background.mjs`. |
